## 1. Что сцена делает сейчас

- 14 тел (Солнце, 8 планет, 5 карликовых) по кеплеровым элементам без вековых
  поправок; 10 лун по круговым орбитам; 3000 случайных астероидов; 15 000
  случайных звёзд.
- Масштаб смешанный: 1 а.е. = 40 единиц, радиус тела = `log10(км)`-кривая
  (Земля ≈ 1.0, Солнце 6).
- Время: rAF-цикл в React-состоянии, режимы «вживую / 1 день/с / 1 мес/с»,
  перемотка удвоением.
- Пост-обработка: Bloom, Vignette, ChromaticAberration; тени от точечного
  света 4096².

## 3. Как это сделано «у больших» и что взять

NASA Eyes on the Solar System, Celestia, Stellarium, JPL Horizons-viewer — все они
строятся на одном принципе: **позиции из эфемерид (SPICE/JPL), а не из
констант**, реальные текстуры с известной лицензией, и честная работа с масштабом.

### 3.2 Справочные данные для панели

- **NASA Planetary Fact Sheet** (`nssdc.gsfc.nasa.gov/planetary/factsheet/`) —
  масса, радиус, гравитация, температуры, период вращения, наклон оси, состав
  атмосферы для планет, Луны, Плутона. Это закрывает B2, B6 одним заходом.
- JPL SBDB — физические параметры карликовых планет и астероидов.
- Строки для трёх локалей: имена тел и подписи панели (B7).

### 3.3 Спутники и аппараты («sun'iy yo'ldoshlarni qo'shish»)

Уже есть: `satellite.js` (SGP4) и весь код парсинга TLE и рендера точек в
`LiveSpaceView.jsx` — его можно поднять в общий модуль и подключить к режиму
«Земля» в солнечной системе.

- **CelesTrak GP** (`celestrak.org/NORAD/elements/gp.php?GROUP=…&FORMAT=json`) —
  группы `stations` (МКС, Тяньгун), `starlink`, `gps-ops`, `galileo`, `glo-ops`,
  `weather`, `science`, `geo`, `active`. **Политика с 26 марта 2026: одна
  загрузка на обновление** (обновления ~раз в 2 ч), 50 HTTP-ошибок за 2 ч →
  IP в файрвол. Значит: тянет только бэкенд, раз в 2 часа, клиент получает наш
  `/api/v1/space/gp/?group=stations` из кэша. Сейчас `/live` делает три
  запроса с каждого браузера — это надо переделать до любого массового
  показа.
- Аппараты в дальнем космосе — через Horizons (см. 3.1): Voyager 1/2, New
  Horizons, JWST (в L2), Parker Solar Probe, Juno, Mars-орбитеры. Траектории —
  линиями, модели — из **NASA 3D Resources** (`nasa.gov/3d-resources`,
  `github.com/nasa/NASA-3D-Resources`; glb, public domain): ISS, Hubble, JWST,
  Voyager, Cassini, Juno, Perseverance.
- Запуски: **r/SpaceX API (`api.spacexdata.com`) архивирован в июне 2026 и
  отдаёт TLS 525 — не использовать.** Уже подключённая **Launch Library 2**
  (`ll.thespacedevs.com`) — 15 запросов/ч без ключа; с бесплатным ключом
  больше. Тоже через бэкенд-кэш (D3).

### 3.4 Бэкенд-прокси с кэшем

Одно Django-приложение `apps/space` с тремя вьюхами и `django.core.cache`
(в проде — Redis или таблица; Neon общая, писать в неё по расписанию, а не по
запросу):

| Эндпоинт | Источник | TTL |
|---|---|---|
| `GET /api/v1/space/gp/?group=` | CelesTrak GP JSON | 2 ч |
| `GET /api/v1/space/ephemeris/?body=&from=&to=` | JPL Horizons vectors | 24 ч |
| `GET /api/v1/space/launches/` | Launch Library 2 | 1 ч |
| `GET /api/v1/space/apod/` | api.nasa.gov с настоящим ключом в `.env` | 12 ч |

Клиент никогда не ходит во внешние хосты напрямую — школьные сети их
блокируют, а лимиты считаются по IP школы.

### 3.5 Текстуры и фон

| Ресурс | Лицензия | Что брать |
|---|---|---|
| **Solar System Scope Textures** (`solarsystemscope.com/textures`) | CC BY 4.0 | 2k-карты всех планет, Луны, Цереры, Эриды, Хаумеа, Макемаке; кольца Сатурна с альфой; звёздная карта. Указать атрибуцию в `ATTRIBUTION.md`. |
| **NASA SVS CGI Moon Kit** (`svs.gsfc.nasa.gov/4720`) | public domain | Цвет и высоты Луны из LRO, 2k–27k. |
| NASA Blue Marble / Visible Earth | public domain | Земля день/ночь/облака — уже в `/textures`. |
| **NASA SVS Deep Star Maps 2020** (`svs.gsfc.nasa.gov/4851`) | public domain | Настоящее небо с Млечным Путём, правильно ориентированное в J2000 — вместо 15 000 случайных `<Stars>`. 8k equirect ≈ 3–4 МБ в KTX2. |
| NASA SDO | public domain | Реальная поверхность Солнца. |
| USGS Astrogeology | public domain | Марс, Меркурий, галилеевы спутники в высоком разрешении. |

Формат: конвертировать в **KTX2/Basis** (`toktx` или `gltf-transform`) и грузить
через `useKTX2` из drei — размер ~в 4 раза меньше и текстура не распаковывается
в RGBA в видеопамяти. Бюджет CI на большие файлы (> 2 МБ) остаётся в силе.

### 3.6 Приёмы рендера

- **Масштаб.** Реальный масштаб делает планеты невидимыми; Eyes решает это
  иконками и лейблами, Celestia — переключателем. Оставить наш смешанный масштаб,
  но добавить переключатель «истинный масштаб» — это само по себе урок.
- **Точность глубины.** `logarithmicDepthBuffer` либо плавающий origin
  (сцена сдвигается так, что камера всегда около нуля) — иначе дрожание при
  приближении к Эриде на 2700 единицах.
- **Атмосфера.** Небольшой fresnel-шейдер (рассеяние по краю) вместо второй
  сферы с `AdditiveBlending`: Земля, тонкая у Марса, плотная у Венеры и Титана.
- **Земля.** Ночные огни (есть), спекуляр океанов (есть), тень облаков на
  поверхности, терминатор от реального направления на Солнце (следует из
  правильного освещения V4).
- **Солнце.** Эмиссивный HDR-материал + селективный bloom + lens flare
  (`three/examples/jsm/objects/Lensflare`).
- **Кольца.** Свои UV + альфа + тень планеты на кольцах в шейдере.
- **Пояс, Койпер, кометы.** Инстансы с элементами в атрибутах, позиция в
  вершинном шейдере; кометы с хвостом «от Солнца».
- **Когда пауза — `frameloop="demand"`**, нулевая нагрузка.

## 4. План внедрения

Порядок важен: сначала то, что делает сцену быстрой и честной, потом красота.

| Этап | Содержание | Оценка |
|---|---|---|
| **0. Стоп-кровотечение** | A1–A4, V1–V5, B3, B5, C1–C2, D2. Без редизайна и новых данных. Метрика: стабильные 60 fps на встроенной графике при `dpr 1.5`, отсутствие предупреждений three в консоли. | 1–2 дня |
| **1. Данные** | `astronomy-engine`: позиции, вращение (`RotationAxis`), Луна, галилеевы спутники; таблица Fact Sheet в `solarSystemData.js`; i18n панели и имён; выбор даты + «Сегодня»; ограничение диапазона; пояс из SBDB на GPU (A5, B1–B9). | 3–4 дня |
| **2. Картинка** | Текстуры SSS 2k + Moon Kit + Deep Star Maps в KTX2, атмосферный шейдер, кольца, Солнце, LOD, прогресс загрузки (V6–V7, A6–A7, §3.5–3.6). | 4–5 дней |
| **3. Спутники и аппараты** | `apps/space` с кэшем; режим «Земля» со спутниками из общего с `/live` модуля; Voyager/JWST/Parker/New Horizons по Horizons с моделями NASA; перевод `/live` на бэкенд-прокси (§3.3–3.4, D3). | 4–5 дней |
| **4. Управление** | Зум относительно цели, damping, `zoomToCursor`, «Обзор»/`Esc`, список тел, клавиатура, тач-раскладка, экранные лейблы, хитбоксы (C3–C7). | 2–3 дня |
| **5. Образовательный слой** | Переключатель истинного масштаба; события из astronomy-engine (затмения, противостояния, фазы Луны) как метки на шкале времени; привязка к квизам («где сейчас Марс?»). | по мере сил |

Итого ≈ 3 рабочие недели для одного разработчика; этапы 1 и 2 можно вести
параллельно двумя людьми, 3 — отдельно на бэкенде.

## 5. Что проверить сразу после этапа 0

1. Консоль: ноль предупреждений three за минуту работы.
2. Позиция Земли на сегодня против Horizons: расхождение < 0.1°.
3. Луна — рядом с Землёй, Уран не кувыркается.
4. На телефоне 390 px панель времени помещается целиком.
5. `git status` чистый после `npm install` на Windows.
